## 1. 한눈에 보기

**서비스 한 줄:** 기보를 KataGo 로 수마다 분석해 등급(최선~악수)·집손해·승률 변화를 보여주고, 그 결과를 복기·오답노트·실력 리포트·기력 추정으로 재가공한다. 부가로 AI 대국, 빈 판 실시간 분석, 사활 문제가 있다.

### 3.3 데이터 구조

#### 착수 (Move)

| 필드     | 뜻                                                           |
| -------- | ------------------------------------------------------------ |
| `color`  | `"B"` · `"W"`                                                |
| `x`, `y` | 0~18. **y 는 아래쪽이 0** (GTP 행 번호 − 1). 패스는 `-1, -1` |

#### 게임 (Game) · 기보 원본

- 게임 = 파일명 + 착수 목록. 대국자·결과·날짜·덤·핸디캡을 담는 구조가 **없다.**
- 기보 원본은 파일 그대로 보관한다 (`.sgf` 67 · `.gib` 1, 실측).
- "내 기보 / 프로 기보" 는 **파일명 문자열**로만 구분한다.

#### 분석 결과 (한 판)

| 필드                                                                               | 뜻                                                                  |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `id`                                                                               | UUID. 결과 파일 이름                                                |
| `fileName`                                                                         | 원본 기보 파일명                                                    |
| `blackPlayer`, `whitePlayer`                                                       | SGF 에서만 추출 (GIB 는 null)                                       |
| `analyzedAt`                                                                       | ISO 로컬 일시 (시간대 없음)                                         |
| `totalMoves`                                                                       | 수                                                                  |
| `engineNet`, `analysisVisits`, `deepVisits`, `deepMoveCount`, `analysisDurationMs` | 분석 메타. 구 결과는 null                                           |
| `moves[]`                                                                          | 수별 분석 (아래)                                                    |
| `top3Mistakes[]`                                                                   | 집손해 큰 수 3개                                                    |
| `top3GoodMoves[]`                                                                  | 집 이득 수 3개 — **항상 비어 있음** ([5.1](#51-동작하지-않는-기능)) |
| `opening`, `middle`, `endgame`                                                     | 구간 통계 (아래)                                                    |

#### 수별 분석 (MoveDetail)

| 필드                                | 뜻                                                                           | 관점                    |
| ----------------------------------- | ---------------------------------------------------------------------------- | ----------------------- |
| `turnNumber`                        | 1부터                                                                        |                         |
| `color`, `move`                     | 둔 색, GTP 좌표 (`"D4"`, `"pass"`)                                           |                         |
| `bestMove`                          | KataGo 1순위 수 (방문·신뢰 종합)                                             |                         |
| `topMoves[]`                        | 추천수 3개 **(둘 쪽 승률 순 재정렬)**                                        |                         |
| `bestPv[]`                          | 최선수 이후 예상 진행, 최대 8수                                              |                         |
| `candidates[]`                      | 추천수 3개 상세 `{move, winrate(0~1), scoreLead, pv[최대 6]}`                | **흑 기준**             |
| `matchesBest`                       | 실제 수 = `bestMove`                                                         |                         |
| `winrateBefore`, `winrateAfter`     | 착점 전·후 승률 (0~1)                                                        | **흑 기준**             |
| `winrateLoss`                       | 둔 쪽 기준 승률 손실                                                         | 둔 쪽                   |
| `scoreLeadBefore`, `scoreLeadAfter` | 착점 전·후 집차                                                              | **흑 기준** (+흑 / −백) |
| `scoreLoss`                         | 최선 대비 집손해, **0 이상으로 자름**                                        | 둔 쪽                   |
| `grade`                             | `최선` · `좋음` · `보통` · `실수` · `악수` (구 결과는 `S`~`D`)               |                         |
| `phase`                             | `초반` · `중반` · `종반`                                                     |                         |
| `deepAnalyzed`                      | 2차 정밀 재분석 여부                                                         |                         |
| `ownership[361]`                    | 착점 **후** 국면 집 예측. +흑 / −백, 인덱스 규칙 [3.4](#34-좌표와-관점-규칙) | 흑 기준                 |

실측: 결과 83건 중 `ownership` 보유 63건, `candidates` 보유 60건, 구 등급(S~D) 178수. 판당 JSON 크기 **중앙값 355 KB · 최대 927 KB** (대부분 `ownership`).

| 갤러리 카드    | id · 제목 · 프로 여부 · 날짜 · 수 · 일치율 · 구간별 집손해 · 최고/최저 구간 · 썸네일 수순(앞 80수)                 | 갤러리 · 소개     |
| 오답 카드      | 결과 id · 파일 · 대국자 · 일시 · 수번 · 색 · 실제 수 · 최선수 · 등급 · 집손해 · 구간 · 썸네일 수순(그 수 직전까지) | 오답노트 · 리포트 |
| 대국자 기력    | [3.5](#기력-인증-신뢰도-기복-성장) 의 모든 값 + 구간별 기력 + 판별 집손해 추이                                     | 인증서 · 리그     |

썸네일 수순은 `"BQ16,WD4,…"` 형태의 **압축 문자열**이다.

#### 사활 문제

`id` · `boardSize(5~19)` · `difficulty` · `toPlay` · `prompt` · `stones[{color, at(GTP)}]` · `answers[](정답 첫 수, 복수)` · `solution[](정해)` · `region[xMin, yMin, xMax, yMax]` (번들 75문제)

#### 계정

`username` · `email` · `displayName` · `passwordHash` · `createdAt`

### 3.4 좌표와 관점 규칙

**새 구현에서 가장 틀리기 쉬운 부분이다.** 여기 규칙을 그대로 지켜야 기존 데이터와 같은 값이 나온다.

| 대상           | 규칙                                                                                  |
| -------------- | ------------------------------------------------------------------------------------- |
| GTP 좌표       | 열 `A~T` 에서 **`I` 를 건너뜀**(19열). 행 `1~19` 는 **아래에서 위로**                 |
| SGF 좌표       | `aa~ss`. 행은 **위에서 아래로** → GTP 와 행이 뒤집힌다                                |
| 화면 좌표      | 행 0 이 위. GTP 행 `y` 는 화면 `18 − y`                                               |
| `ownership[i]` | 인덱스 = `(18 − gtpY) × 19 + x`. 즉 **위쪽 행부터** 채운 1차원 배열                   |
| 패스           | GTP `"pass"`, 좌표 없음                                                               |
| 차례           | **마지막 착수의 반대 색.** 빈 판은 흑. 수 개수 짝홀로 판단하지 않는다 (백선착·접바둑) |
| 규칙 · 덤      | 한국 규칙, 덤 6.5                                                                     |

**승률·집차의 관점이 필드마다 다르다.**

| 값                                              | 기준         | 단위          |
| ----------------------------------------------- | ------------ | ------------- |
| 분석 결과 `winrate*` · `candidates.winrate`     | 흑           | 0~1           |
| 분석 결과 `scoreLead*` · `candidates.scoreLead` | 흑 (+흑/−백) | 집            |
| `/api/play/hint`                                | **내 색**    | %, 소수 1자리 |
| `/api/analyze/top` `rootWinrate` · `candidates` | **둘 차례**  | %             |
| `/api/analyze/top` `rootScoreLead`              | 흑           | 집            |
| `/api/play/estimate`                            | 흑           | 승률 0~1, 집  |
| `scoreLoss` · `winrateLoss` · 대국 `userLoss`   | 둔 쪽        | 집 / 0~1      |

> 새 API 는 **관점과 단위를 하나로 통일**한다. (권장: 모든 값 흑 기준 0~1, 화면에서 변환)

### 3.5 판정 규칙

#### 수 등급 (집손해 기준)

| 등급 | 집손해 |
| ---- | ------ |
| 최선 | < 0.5  |
| 좋음 | < 1.5  |
| 보통 | < 3    |
| 실수 | < 5    |
| 악수 | ≥ 5    |

같은 임계값을 **복기 · 대국 실시간 평가 · 분석판 수 품질**이 모두 쓴다. 실측 분포(83판): 최선 9,658 · 좋음 1,365 · 보통 702 · 실수 204 · 악수 262.

#### 집손해 계산

- 착점 **직전** 국면의 최선 기대 집차(흑 기준)와, 그 국면 후보 목록 안의 **실제 수의** 집차를 둔 쪽 기준으로 비교한다.
- 실제 수가 후보 목록에 없으면 착점 전·후 국면 집차를 비교한다.
- 결과는 **0 미만으로 내려가지 않는다.**

#### 구간

초반 1~~50수 · 중반 51~~150수 · 종반 151수~

#### 패착

1. 후보: 집손해 ≥ 1.5 이고, 둔 쪽 승률이 **착점 전 ≥ 40%** 에서 **착점 후 < 50%** 로 떨어진 수
2. 이후 그 쪽 승률이 한 번도 50% 이상으로 회복하지 못한 후보가 있으면 그중에서, 없으면 전체 후보 중에서
3. 승률 낙폭이 가장 큰 수 1개
4. 후보가 없으면 "뚜렷한 패착 없음"

패착 이후 **같은 색**의 실수·악수는 "승부수" 로 표시한다.

#### 기력 구간

한 수당 평균 집손해로 정한다. 복기의 "예상 기력" 과 인증서가 같은 경계를 쓴다.

| 평균 집손해 | 구간                 | 부제         |
| ----------- | -------------------- | ------------ |
| < 0.6       | 아마 최상위 · 프로급 | 약 5단 이상  |
| < 1.0       | 아마 고단자          | 약 1~4단     |
| < 1.8       | 아마 상급            | 약 1~5급     |
| < 3.0       | 아마 중급            | 약 6~12급    |
| < 5.0       | 아마 초·중급         | 약 13~18급   |
| ≥ 5.0       | 입문 · 초급          | 약 19급 이하 |

#### 기력 인증 (신뢰도 · 기복 · 성장)

| 항목      | 규칙                                                                                                              |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| 집계 단위 | **대국자 이름.** 한 판을 흑·백 두 사람 기록으로 나눈다                                                            |
| 기본 대상 | 내 기보에 가장 많이 나온 이름                                                                                     |
| 신뢰도    | 4판 이상 **그리고** 240수 이상 → 확정 / 2판 이상 → 잠정 / 1판 → 표본 부족                                         |
| 기복      | 판별 평균 집손해 표준편차: < 0.5 안정형 / < 1.2 보통 / 그 이상 기복형 / 2판 미만 판단 보류                        |
| 성장      | 판을 분석 순서로 늘어놓고 앞 절반 vs 뒤 절반 평균 집손해. 개선 = 앞 − 뒤 (양수 = 좋아짐). 각 절반 2판 이상일 때만 |
| 구간 막대 | 5집을 상한으로 한 손해 비율                                                                                       |

#### 약점 코멘트

| 코멘트            | 조건                                               | 심각도                               |
| ----------------- | -------------------------------------------------- | ------------------------------------ |
| 반복 약점: {구간} | 5수 이상 구간 중 일치율 최저 (최고 구간과 다를 때) | 일치율 < 40 high, 그 외 mid          |
| 집중 복기: {구간} | 구간이 하나뿐이고 일치율 < 50                      | 〃                                   |
| 큰 실수 빈도      | 악수가 1개 이상                                    | 판당 ≥ 2 high / ≥ 1 mid / 그 외 good |
| {구간} 집 손실    | 5수 이상 구간 중 평균 집손해 최대가 ≥ 1.0          | ≥ 3 high, 그 외 mid                  |
| 강점: {구간}      | 최고 일치율 ≥ 55                                   | good                                 |

#### 레이더 6축

| 축                 | 값 (0~100)             |
| ------------------ | ---------------------- |
| 초반 · 중반 · 종반 | 구간 일치율            |
| 수 품질            | "최선" 등급 비율       |
| 집 지키기          | 100 − 평균 집손해 × 12 |
| 큰 실수 없음       | 100 − 악수 비율 × 5    |

#### 형세 문구

| 화면             | 규칙                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| 대국 힌트        | 최선수 승률 ≥ 60 유리 / ≤ 40 불리 / 그 외 팽팽                               |
| 분석판 요약      | 흑 승률 ≥ 55 흑 우세 / ≤ 45 백 우세 / 그 외 팽팽                             |
| 최종 형세 · 총평 | 집차 절댓값 < 0.5 → 반집 접전                                                |
| 놓아보기 평가    | 직전 최선 승률 − 방금 수 승률: ≤ 2%p 최선급 / < 8%p 조금 낮음 / 그 이상 경고 |

#### 기타

- **일치율(판 전체):** 구간 일치율을 수 개수로 가중평균
- **홈·목록 AI 일치율:** `matchesBest` 비율
- **오답노트:** 실수·악수만, 내 기보만, 집손해 큰 순 최대 200
- **갤러리 정렬 기본:** 사활 → 기보, 기보는 프로 먼저 → 분석 최신순

### 4.4 기보 목록

#### User Goal

분석할 기보를 고르고, 분석이 끝난 판의 결과를 연다.

#### User Flow

1. 요약: 전체 기보 수 · 평균 AI 일치율 · 누적 분석 시간
2. 탭: 전체 · 프로 기보 · 나의 기보 · 분석 완료 · 미분석
3. 검색 · 기간(7일 / 30일 / 3개월 / 전체) · 종류 · 정렬(최근 분석 · 일치율 높은/낮은 · 파일명)
4. 행: 기보 정보 · 분석 상태 · 일치율 링 · 구간별 일치율 막대 3개 · 분석 일시와 소요 · 액션
5. 미분석 → "분석" → 대기 화면 / 분석 완료 → "결과 보기" → 복기
6. (관리) 전체 재분석 → 확인 → 진행 표시

#### API

페이지 GET `/game` · form `POST /game/analyze` · form `POST /game/reanalyze-all` · 폴링 `GET /game/running-jobs`(2초) · `GET /game/reanalyze-all/status`(1.5초)

#### State

전체 행 · 탭 · 검색어 · 기간 · 종류 · 정렬 · 페이지 · 페이지 크기(10/20/50) · 실행 중 작업 목록

#### Interaction

탭 · 필터 · 정렬 · 페이징 전부 클라이언트. 분석 버튼은 폼 제출

#### Business Logic

판 일치율 = 구간 일치율 수 가중평균. 같은 파일 재분석은 최신 결과 1건만

#### UI Behavior

분석 중인 행은 진행률로 바뀜. 전체 재분석 진행 중 배너

#### Migration Priority

**P1.** 새 서비스에서는 "서버 폴더의 파일 목록" 이 아니라 **사용자가 업로드한 내 기보 목록**이 되어야 한다. 업로드 진입점을 이 화면에 둔다. 전체 재분석은 운영 기능이라 P3.

### 4.5 분석 대기 (+ 사활 위젯)

#### User Goal

분석이 끝날 때까지 진행을 확인하고, 기다리는 동안 사활 문제를 푼다.

#### User Flow

1. 파일명 · 총 수 · visits 표시
2. 진행률 · 현재 분석 수 · 경과 · 남은 시간
3. 단계: 기보 파싱 → 1차 수순별 분석 → 2차 정밀 재분석 → 리포트 생성
4. 완료 → "결과 보기" 버튼 (자동 이동 없음) / 실패 → 오류 배너
5. 오른쪽: 사활 문제 풀기

#### API

페이지 GET `/game/waiting/{jobId}` · `GET /game/status/{jobId}`(2초, 실패 시 5초) · `GET /api/tsumego/random?difficulty&exclude`

#### State

**분석:** 진행률 · 상태(RUNNING/DONE/ERROR/UNKNOWN) · 시작 시각 · 결과 id
**사활:** 현재 문제 · 판 상태 · 정해 진행 단계 · 수순 번호 · 완료 여부 · 난이도 · 풀었던 문제 기록(이전/다음 탐색)

#### Interaction

사활: 교차점 클릭(가장 가까운 점, 셀 0.55배 반경) · 난이도 선택 · 이전 · 다음 · 재도전 · 힌트 · 정답 보기 · 닫기 · 도움말

#### Business Logic

- 진행률 < 99 → 1차, ≥ 99 → 2차, 완료 → 전 단계 완료
- 남은 시간 = 경과 × (100 − p) / p
- 사활 정답: 클릭한 점이 **이번 차례 정해 수와 같으면** 정답 → 0.45초 뒤 상대 응수 → 정해 끝이면 완료
- 틀리면 빨간 점 + "다시 시도"
- 자살수 금지, 따냄 적용

#### UI Behavior

완료 시 자동 이동하지 않는다. 서버 재시작으로 작업이 사라지면 "분석 정보를 찾을 수 없음" 으로 멈춘다.

#### Migration Priority

**P0 (분석 진행).** 업로드 → 분석 → 복기 흐름의 필수 단계. 백엔드 방식(폴링/SSE) 확정 필요 ([api-integration.md](api-integration.md#긴-분석-작업)).
**P3 (사활 위젯).** 대기 경험 개선용. 정답 판정은 복수 정답을 처리하도록 고친다 ([5.1](#51-동작하지-않는-기능)).

### 4.6 복기 결과 — 핵심 화면

#### User Goal

내 한 판을 수마다 되짚으며 **어디서, 왜, 얼마나** 손해 봤는지 이해하고, 더 나은 수를 직접 시도해 본다.

#### User Flow

1. 진입: `?move=N` 이 있으면 그 수 → 없으면 **가장 큰 실수** → 없으면 1수
2. 상단: 기보 메타 · 한 줄 총평 배너(최종 형세 · 총평 · 가장 큰 승부처)
3. 판에서 수를 넘기며 현재 수 정보 확인 (수번 · 내가 둔 수와 승률 · 추천 순위 · 집손해 · 등급 · 최선수 · 예상 진행 · 패착 여부)
4. 추천수에 마우스를 올려 예상 진행 확인
5. 필요하면 변화도 · 수순 번호 · 집 예측 토글
6. "비교" 로 내 수와 최선수 이후를 나란히
7. "놓아보기" 로 직접 다른 수를 두며 AI 반응 확인
8. "이 수부터 다시 두기" 로 AI 대국 전환
9. 승부 흐름 그래프 · 핵심 실수 · 패착 카드 · 호수 · 총평 수번을 눌러 해당 수로 점프
10. 오른쪽: 예상 기력 · 구간별 성적 · AI 착수 통계 · 패착 · 핵심 실수 · 호수
11. 하단: 학습 요약 (잘한 점 / 다음에 볼 것)
12. 주석 SGF 내려받기 · 기보 목록으로

#### API

페이지 GET `/game/result/{id}` (결과 전체 인라인) · `POST /api/analyze/top` (놓아보기) · `GET /game/result/{id}/sgf` · 이어두기는 세션 저장 후 `/play` 이동

#### State

| 종류               | 내용                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------- |
| 서버 데이터 (불변) | 수별 분석 전체                                                                          |
| 파생 (1회 계산)    | 핵심 실수 목록 · 실수 수번 집합 · 호수 · 패착 수                                        |
| 화면 상태          | 현재 수 · 수순 번호 표시 · 변화도 표시 · 집 예측 표시                                   |
| hover              | 현재 추천수 마커 목록 · hover 중인 마커                                                 |
| 놓아보기           | 활성 · 기준 수 · 놓은 돌 · AI 추천수 · 추천수 계산 기준 색 · 요청 토큰 · 직전 최선 승률 |

#### Interaction

[3.8](#38-사용자-interaction--키보드--마우스) 의 복기 행 전부. 버튼: 처음 · −5 · 이전 · 다음 · +5 · 끝 · 수번 이동 · 수순 · 변화도 · 비교 · 집 예측 · 놓아보기 · 이어두기

#### Business Logic

[2.1](#21-복기--분석-결과) 표 전체 + [3.5](#35-판정-규칙) (등급 · 패착 · 기력 구간 · 형세 문구 · 놓아보기 평가)

추천수 표시 우선순위: 상세 후보(승률 원) → 후보 좌표만(순위 번호) → 최선수 1개. 구 결과 호환용.

#### UI Behavior

- 방금 수가 추천수와 같으면 빨간 고리 대신 금색 승률%
- 추천수는 빈 자리에만, 실제 수와 같은 후보는 생략
- 변화도 중엔 집 예측 숨김 (안내 문구)
- 비교 버튼은 최선수와 다를 때만 활성
- 처음/끝에서 이동 버튼 비활성
- 놓아보기 중엔 카운터가 "놓아보기 · N수 (다음: 흑)" 으로 바뀌고 이동 단축키 대부분 비활성
- 차트 리사이즈 시 150ms 뒤 다시 그림
- 실수·악수 없으면 "훌륭해요" 빈 상태, 패착 없으면 "뚜렷한 패착 없음"

#### Migration Priority

**P0.** 서비스 가치의 대부분이 여기 있다. 이관 순서 제안:

1. Board 표시 + 수순 이동 + 키보드/휠 + 현재 수 정보 + 승률 막대
2. 추천수 · hover 예상 진행 · 변화도 · 집 예측
3. 승부 흐름 차트 (클릭 이동) · 핵심 실수 · 패착 · 구간 성적 · AI 착수 통계
4. 놓아보기 · 나란히 비교 · 이어두기
5. 총평 · 학습 요약 · 예상 기력 · SGF 다운로드

**반드시 바꿀 것:** 결과 전체(최대 약 900KB)를 한 번에 받지 않는다. 수 목록·통계와 **수별 집 예측을 분리해서** 필요할 때 받는다. "호수" 는 규칙부터 다시 정한다.

### 4.7 AI 대국

#### User Goal

KataGo 와 한 판 두거나, 복기에서 가져온 국면을 이어서 둔다.

#### User Flow

1. 흑/백 선택 → 시작 (백이면 AI 가 먼저 둠)
2. 판 클릭으로 착수 → AI 생각 중 → AI 응수 + 내 수 실시간 평가(등급)
3. 필요할 때: 힌트 TOP 5 · 형세 판단(집 예측) · 무르기 · 패스 · 기권
4. 연속 2패스 → 종료 모달 → 자동 계가
5. 복기에서 왔다면: 그 국면을 즉시 표시하고 "복기 N수 국면에서 이어 두기" 안내 → 내 차례가 아니면 AI 가 먼저 둠

#### API

`/api/play/new` · `/api/play/from` · `/api/play/move` · `/api/play/pass` · `/api/play/hint` · `/api/play/estimate` · `/api/play/undo`

#### State

내 색 · 시작 여부 · 종료 여부 · AI 대기 중 · 수순 · 흑/백 따낸 돌 수 · hover 교차점 · AI 마지막 수 · 힌트 마커 · 집 예측

#### Interaction

판 클릭 · hover 미리보기 · 버튼(무르기 · 패스 · 기권 · TOP 5 보기 · 형세 판단 · 새 대국)

#### Business Logic

- 합법수: 빈 자리 + (상대를 따내거나 자기 활로 있음). **패 금지 없음**
- 무르기: 2수 제거, 내가 백이면 AI 첫 수 유지
- 종료: 연속 2패스
- 기권: 화면에서만 종료 (서버 상태는 남음)
- 실시간 평가: 착수 전 최선 기대 집차 vs 착수 후 집차, 등급 규칙 동일
- 힌트 형세: 최선 승률 60/40 기준
- 계가: 집 예측 기반 집차 추정

#### UI Behavior

- 오른쪽: 생각 중 → 현재 형세 → 추천수 TOP5 → AI 한마디(착수 평가·형세) → 대국 정보(현재 수 · 내 돌 · 따낸 돌)
- 오류는 `alert()`
- 힌트는 버튼을 눌러야만 요청 (GPU 비용)

#### Migration Priority

**P2.** **서버의 대국 상태가 서버 전체에 하나뿐이다** ([5.2](#52-구조적-문제)). 새 백엔드에서 대국을 사용자·게임 단위로 분리하기 전까지 화면만 목 데이터로 만든다.

### 4.8 실시간 분석판

#### User Goal

빈 판(또는 원하는 국면)에 흑백을 직접 놓으며 AI 추천수와 형세 변화를 연구한다.

#### User Flow

1. 빈 판에서 시작, 흑부터
2. 착수할 때마다 추천수 5개 · 승률 · 집 예측 갱신
3. 추천수에 hover → 예상 진행
4. 무르기 · 다시 두기 · 패스 · 전체 지우기
5. 오른쪽 대시보드: 승률 그래프 → 예상 집차와 추이 → 수 품질 분포 → 추천수 TOP5 표 → 최근 승률 하락 TOP3 → AI 코멘트 · 국면 요약

#### API

`POST /api/analyze/top` (착수마다)

#### State

놓인 돌 · 무른 돌 스택 · 다음 색 · 추천수 · hover 예상 진행 · 집 예측 · 직전 최선 승률 · 요청 토큰 · 좌표 표시 · 집 예측 표시 · **착수별 누적 시리즈 [수번 · 흑 승률 · 흑 기준 집차 · 둔 수 · 색]**

#### Interaction

판 클릭 · hover · 휠(위=무르기, 아래=다시두기) · 버튼 · 토글(집 예측 · 좌표) · 추천수 표 행 클릭

#### Business Logic

- 새 착수 시 다시두기 스택 초기화
- 무르기 시 누적 시리즈 뒤를 잘라냄
- 수 품질 = 직전 국면 최선 집차 − 실제 집차 → 등급 규칙 동일
- 승률 하락 = 둔 쪽 관점 0.5%p 초과, 큰 순 3개
- 흑 ≥ 55 / ≤ 45 우세 판정
- 판 크기: 넓은 화면은 판 영역 가로·세로 중 작은 쪽, 좁은 화면은 가로 폭 기준 + 화면 높이 74% 상한, 280~1000px

#### UI Behavior

- 3열 [도구 190px | 판 | 대시보드], 1150px 이하 [요약 / 판 / 버튼]
- 분석 설정(visits · 덤)은 서버 실제 값을 표시
- 새 요청 시 이전 추천수를 즉시 숨김

#### Migration Priority

**P1.** 복기의 놓아보기와 **같은 Board · 같은 분석 API · 같은 등급 규칙**을 쓴다. 복기를 만들며 생긴 부품을 그대로 조립할 수 있어 비용이 낮다. 무상태 API 라 백엔드 재설계 부담도 없다.

### 4.9 실력 리포트

#### User Goal

여러 판에 걸친 내 실력의 강점·약점과 변화를 보고, 다음에 무엇을 공부할지 안다.

#### User Flow

1. 기간 선택 (최근 30판 / 전체)
2. 요약: 한 줄 요약 · 평균 AI 일치율 · 직전 N판 대비 변화 + **가장 크게 손해 본 실수 국면 판**
3. 지표 4개
4. 실력 변화 추이 + 밸런스 레이더
5. 구간별 분석 (프로 기보 대비 포함)
6. 강점 · 반복 실수 코멘트
7. 최근 분석 기보 표 → 복기
8. 다음 학습 추천

#### API

페이지 GET `/analysis/batch` (구간 집계 내/프로 · 판 수 · 약점 코멘트 · 판 요약 행 · 구간별 프로 일치율 · 집손해 1위 실수 · 실수 총수)

#### State

판 요약 목록 · 선택 기간 · 계산된 지표

#### Interaction

기간 버튼 · 표 행 클릭

#### Business Logic

[3.5](#35-판정-규칙) 의 약점 코멘트 · 레이더 · 일치율. 변화량 = 최근 N판 vs 직전 N판. 기간 전환은 받은 목록을 잘라 재계산

#### UI Behavior

판 요약 · 추이 · 표가 같은 데이터를 공유. 가짜 수치 없이 데이터 없으면 빈 상태

#### Migration Priority

**P2.** 복기 결과가 쌓여야 의미가 있다. 승/패 데이터는 기존에도 없다(기보 결과를 저장하지 않음). 약점 문구는 서버가 HTML 을 만들지 말고 **구조화된 값**으로 받아 화면이 문장을 만든다.

## 5. 기존 구현의 문제 — 새 프로젝트에서 반복하지 않는다

### 5.1 동작하지 않는 기능

| 문제                                           | 근거                                                                                                                                 | 새 프로젝트                                                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| **"호수"(집 이득 수)가 한 번도 표시되지 않음** | 집손해를 0 미만으로 자르는데, 호수는 집손해 ≤ −2 인 수를 찾는다. **실측: 결과 83건 중 호수 데이터가 있는 판 0건**, 전체 최솟값 −0.39 | 규칙을 새로 정의한다. 예: 승률·집차를 크게 **올린** 수, 또는 어려운 국면에서 최선수를 찾은 수 |
| 사활 복수 정답 무시                            | 정해 수순이 있으면 그 첫 수만 정답으로 인정. 정답 첫 수 목록(복수)을 쓰지 않음                                                       | 첫 수는 정답 목록 전체로 판정                                                                 |
| 리포트 자동 새로고침                           | "집계 중" 플래그가 항상 거짓                                                                                                         | 새로고침 로직 불필요                                                                          |
| 기권                                           | 화면만 종료, 서버 대국 상태는 그대로                                                                                                 | 서버에 종료 전달                                                                              |

### 5.2 구조적 문제

| 문제                                | 영향                                                                                        | 새 프로젝트                                 |
| ----------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------- |
| **AI 대국 상태가 서버 전체에 하나** | 두 사람이 동시에 두면 서로의 판이 섞인다                                                    | 게임 ID 단위 상태                           |
| **데이터 소유자 없음**              | 모든 계정이 같은 기보·결과·오답노트를 본다. "내 기보" = 파일명에 특정 기사 이름이 없는 파일 | 기보·결과·노트를 사용자에 귀속              |
| **프로 기보 구분이 파일명 문자열**  | 다른 프로 기보를 추가할 수 없다                                                             | 기보 메타데이터(출처·대국자·프로 여부)      |
| **바둑판 로직이 8곳에 복붙**        | 복기 · 대국 · 분석판 · 사활 · 홈 · 리포트 · 오답노트 · 갤러리가 각자 따냄·합법수를 구현     | `features/game/model` 한 곳 + 단위 테스트   |
| **패(ko) 규칙 없음**                | 대국·놓아보기·분석판에서 패를 바로 되따낼 수 있음                                           | 합법수 판정에 패 포함                       |
| **핸디캡 배치 · 판 크기 미지원**    | SGF 의 배치돌(AB/AW)을 무시 → 접바둑 기보의 판이 틀림. 분석은 19줄 고정                     | 파서가 배치돌·판 크기·덤·결과·날짜를 읽는다 |
| **GIB 대국자명 없음**               | GIB 기보는 대국자가 비어 인증서 집계에서 빠진다                                             | 파서 보강                                   |
| **작업 상태가 메모리에만**          | 서버 재시작 시 진행 중 분석이 "알 수 없음"                                                  | 작업 상태 영속                              |
| **결과 전체를 HTML 에 인라인**      | 판당 최대 약 900KB 를 매 진입마다                                                           | 요약 / 수 목록 / 수별 집 예측을 나눠 받는다 |
| **등급 체계 혼재**                  | 구 등급 S~D 가 178수 남아 있고 새 화면은 구 등급을 모름                                     | 이관 시 재분석 또는 변환 규칙               |
| **구 결과에 집 예측·후보 없음**     | 83건 중 20건 집 예측 없음, 23건 후보 없음                                                   | 화면이 필드 부재를 처리하거나 재분석        |

PROJECT.md 의 개발 순서(Design System → Layout → Components → Pages → Mock Data → … → API → Auth)에 맞춘다. **API 가 없어도 목 데이터로 화면을 먼저 만든다.**

| 우선순위 | 대상                                                                         | 이유                                                                                 |
| -------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **P0**   | 복기 결과 · 분석 대기(진행) · **기보 업로드(신규)** · Board · 승부 흐름 차트 | 서비스의 핵심 가치이자 첫 사용 흐름. Board 는 이후 모든 화면의 부품                  |

### 결정이 필요한 것

1. **사활**을 `features/gallery` 에 둘지, 별도 feature 로 둘지
2. **기력 인증서 · 리그**를 `features/analysis` 에 둘지, 별도 feature 로 둘지
3. **"내 기록"의 기준** — 계정 소유 기보만인가, 기보 속 대국자 이름도 쓰는가
4. **호수** 규칙
5. **긴 분석 작업** 전달 방식 — 폴링 / SSE
6. 구 등급(S~D) 결과를 **재분석할지, 변환할지, 버릴지**
