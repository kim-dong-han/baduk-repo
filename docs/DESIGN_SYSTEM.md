# 디자인 시스템

이 문서는 **모든 페이지가 같은 시각 언어를 쓰게 만드는 규칙**이다. 특정 페이지의 디자인이 아니다.

- 토큰 값: [`src/styles/tokens.css`](../src/styles/tokens.css)
- Tailwind 매핑과 base 스타일: [`src/styles/globals.css`](../src/styles/globals.css)
- JS/Canvas 에서 토큰 읽기: [`src/lib/design/tokens.ts`](../src/lib/design/tokens.ts)
- 컴포넌트 분리 규칙: [`COMPONENT_RULES.md`](COMPONENT_RULES.md)
- 눈으로 확인: `npm run dev` → `/design-system`

---

## 1. 이 서비스가 어떤 얼굴이어야 하는가

**Modern Go Study Platform.**

Calm · Professional · Warm · Minimal · Editorial · Human

차분하고, 믿을 만하고, 전문적이고, 사람이 손으로 만든 것 같아야 한다. Editorial 은 잡지 지면처럼 **읽는 순서가 먼저 보이는** 화면을 뜻한다. 카드 격자에 정보를 흩어놓는 대시보드가 아니다.

**하지 않는 것.** 보라·네온·강한 그라디언트, 과한 유리 효과, 모든 것을 카드로 감싸기, 30px 짜리 둥근 모서리, 짙은 그림자, 작은 글씨에 정보 욱여넣기, 의미 없는 배지, 3열 카드 대시보드의 반복. 이런 화면은 어느 AI SaaS 템플릿에서나 본 적 있는 얼굴이 된다.

**대신 지키는 것.**

1. 바둑판이 시각적 중심이다. AI 기능이 아니라 바둑이 주인공이다.
2. 콘텐츠를 읽는 순서가 레이아웃보다 먼저다.
3. 모든 영역을 카드로 감싸지 않는다. 대부분의 내용은 배경 위에 그냥 놓인다.
4. 영역을 나눌 때 선과 카드보다 **여백**을 먼저 쓴다.
5. 중요도 차이는 색이 아니라 **타이포그래피**로 만든다.
6. 작은 글씨로 많은 정보를 넣지 않는다.
7. 장식보다 정보 구조가 먼저다.

## 2. 토큰은 3층이다

```
1층 원시(palette)   --blue-600, --warm-900, --wood-500
       ↓
2층 의미(semantic)  --accent, --text-primary, --board-surface
       ↓
3층 Tailwind 매핑    bg-accent, text-ink-muted, bg-board
```

**컴포넌트는 3층만 쓴다.** 1층을 직접 참조하면 서비스 톤을 바꿀 때 전부 뒤져야 한다. 1층 값만 고쳐서 분위기 전체가 바뀌는 상태를 유지한다.

색 공간은 `oklch` 다. 명도(L)를 고정한 채 색상만 옮길 수 있어 여러 색의 대비를 같은 수준으로 맞추기 쉽다.

Tailwind 기본 팔레트는 **통째로 지웠다**(`--color-*: initial`). `bg-purple-500`, `text-slate-400` 같은 클래스는 존재하지 않는다. 토큰에 없는 색은 쓸 수 없다.

## 3. 색상 토큰

### 표면과 텍스트

배경은 순백이 아니라 따뜻한 종이색(`oklch(0.988 0.003 85)`)이고, 본문은 순검정이 아니라 먹빛이다. 양 극단을 피하면 오래 봐도 눈이 덜 부신다. 회색 계열은 전부 따뜻한 쪽(hue 65~85)이다. 차가운 회색은 화면을 병원처럼 만든다.

| 의미 토큰          | 유틸리티          | 용도                       | 대비(페이지 배경 기준) |
| ------------------ | ----------------- | -------------------------- | ---------------------- |
| `--surface-page`   | `bg-page`         | 페이지 배경 (기본)         | —                      |
| `--surface-raised` | `bg-raised`       | 실제로 띄워야 하는 표면    | —                      |
| `--surface-sunken` | `bg-sunken`       | 가라앉은 영역, 코드 블록   | —                      |
| `--surface-scrim`  | `bg-scrim`        | 모달 뒤를 덮는 막          | —                      |
| `--text-primary`   | `text-ink`        | 본문                       | 15.9:1                 |
| `--text-strong`    | `text-ink-strong` | 제목                       | 19.4:1                 |
| `--text-secondary` | `text-ink-muted`  | 보조 설명                  | 4.8:1                  |
| `--text-tertiary`  | `text-ink-faint`  | 캡션·라벨 전용 (본문 금지) | 3.0:1                  |

`bg-raised` 는 기본값이 아니다. **분리가 필요할 때만** 쓴다.

### 동작과 상태

| 역할    | 토큰                           | 색                                                           |
| ------- | ------------------------------ | ------------------------------------------------------------ |
| Primary | `--accent`                     | 차분한 잉크빛 파랑 `oklch(0.47 0.115 248)` — 흰 글자로 4.9:1 |
| Success | `--success`                    | 차분한 초록                                                  |
| Warning | `--warning` / `--warning-icon` | muted gold — 텍스트용과 아이콘용이 다르다                    |
| Danger  | `--danger`                     | 차분한 빨강                                                  |
| Info    | `--info`                       | Primary 와 같은 파랑                                         |

### Primary 와 Accent 의 관계

두 이름이 문서마다 다르게 쓰여 혼동하기 쉬워 여기서 못박는다.

- **Primary(바탕)** — 화면을 지배하는 것은 따뜻한 종이색, 먹빛 텍스트, 그리고 바둑판의 나무색이다. 이것이 서비스의 기본 색이며 별도의 "primary 버튼 색"이 화면을 물들이지 않는다.
- **Accent(포인트)** — `--accent` 의 차분한 파랑. AI 분석과 상호작용(링크, 주요 동작, 포커스, AI 최선수)에만 **제한적으로** 쓴다.

즉 파랑은 바탕이 아니라 포인트다. 한 화면에서 accent 가 여러 군데 나타나면 이미 과하게 쓴 것이다.

`--color-primary` 라는 이름이 하나 더 있는데, 이것은 shadcn/ui 호환용 별칭일 뿐이다. 새 코드에서는 쓰지 않는다.

### Warning 이 둘인 이유

노란색은 밝을수록 텍스트로 쓸 수 없다. 그래서 warning 만 **텍스트용(`--warning`, L 0.45)과 채움/아이콘용(`--warning-icon`, L 0.62)** 을 따로 둔다. 밝은 금색 위에 흰 글자를 얹는 실수를 막기 위해서다.

각 상태는 `-surface`(연한 배경)와 `-border` 짝을 갖는다. 상태를 **색만으로 알리지 않는다.** 아이콘이나 문구를 반드시 함께 붙인다.

### 바둑판

| 토큰                                                    | 용도                          |
| ------------------------------------------------------- | ----------------------------- |
| `--board-surface` / `-light`                            | 판 바탕 (비자나무 톤)         |
| `--board-surface-edge` / `--board-frame`                | 판 테두리와 두께              |
| `--board-line` / `--board-line-edge`                    | 격자선, 외곽 격자선           |
| `--board-star` / `--board-coord`                        | 화점, 좌표 문자               |
| `--board-hover` / `--board-last-move`                   | 착수 미리보기, 마지막 수 표시 |
| `--stone-black` / `--stone-white` (+ `-edge`, `-sheen`) | 돌 본체·외곽선·광택           |
| `--stone-shadow`                                        | 돌 그림자                     |
| `--stone-label-on-black` / `-on-white`                  | 돌 위 수순 숫자               |

돌에 외곽선을 두는 이유는 흰 돌이 밝은 판에, 검은 돌이 어두운 판에 묻히지 않게 하기 위해서다.

### 분석 신호 (예약된 상태 색)

`--move-best` · `--move-good` · `--move-inaccuracy` · `--move-mistake` · `--move-blunder`.

**이 다섯은 예약되어 있다. 차트 시리즈 색으로 재사용하지 않는다.** 각각 `-surface` 짝을 가지며, 색만으로 구분하지 않고 항상 이름과 수치를 함께 보여준다.

승률 표시는 임의의 색을 입히지 않고 `--winrate-black` / `--winrate-white`, 즉 **돌 색 자체**를 쓴다. 흑의 승률을 파랑으로 칠하면 읽는 사람이 한 번 더 번역해야 한다.

## 4. Typography 토큰

한국어 가독성이 기준이다. 데스크톱에서 작은 글씨를 쓰지 않는다.

| 유틸리티    | 크기     | 행간 | 용도                  |
| ----------- | -------- | ---- | --------------------- |
| `text-5xl`  | 40px     | 1.2  | 페이지 제목 (상한)    |
| `text-4xl`  | **32px** | 1.3  | 페이지 제목           |
| `text-3xl`  | 28px     | 1.35 | 섹션 제목 (상한)      |
| `text-2xl`  | **24px** | 1.35 | 섹션 제목             |
| `text-xl`   | 20px     | 1.55 | 블록 제목             |
| `text-lg`   | 17px     | 1.7  | 상세 본문             |
| `text-base` | **16px** | 1.7  | 본문 기본 — 하한      |
| `text-sm`   | 14px     | 1.6  | 보조 설명 — 하한      |
| `text-xs`   | **13px** | 1.55 | 작은 메타 정보 — 하한 |

밴드로 보면 이렇다. 페이지 제목 **32~40px**, 섹션 제목 **22~28px**, 본문 **16px 이상**, 보조 설명 **14px 이상**, 작은 메타 정보 **13px 이상**.

**13px 미만과 40px 초과는 스케일에 존재하지 않는다.** `text-6xl` 이나 `text-[11px]` 을 쓰고 싶어지면 정보 구조를 다시 본다.

> **정보를 더 넣으려고 글자를 줄이지 않는다.** 사용자가 실제로 읽어야 하는 내용에는 충분한 크기와 행간을 준다. 공간이 모자라면 글자가 아니라 정보를 줄인다.

행간이 라틴 기준보다 넉넉한 1.7 인 것은 한글의 글자 밀도 때문이다. 1.5 를 주면 한국어 문단은 답답해 보인다.

- 폰트: Pretendard(jsDelivr dynamic subset) → 시스템 한글 폰트 폴백
- 굵기: 400 / 500 / 600 / 700 네 단계만
- 숫자: 승률·집 차이·수순처럼 값이 바뀌는 숫자에는 `tabular` 를 붙인다. 안 붙이면 수를 넘길 때 숫자가 좌우로 떨린다.

> 폰트는 지금 CDN 한 번의 외부 요청에 의존한다. 셀프 호스팅으로 옮기려면 woff2 를 `public/fonts` 에 두고 `index.html` 의 링크를 `@font-face` 로 바꾼다. 폰트가 없어도 시스템 한글 폰트로 읽히게 폴백을 깔아 두었다.

## 5. Spacing 토큰

4px 배수 사다리만 쓴다.

```
4    8    12   16   24   32   40    48    64    80
p-1  p-2  p-3  p-4  p-6  p-8  p-10  p-12  p-16  p-20
```

이 사다리 밖의 값(`mt-[13px]`, `gap-7`)을 새로 만들지 않는다. 페이지마다 임의의 여백이 생기면 화면끼리 미묘하게 어긋난다.

기준점 몇 개:

- 섹션 사이 **64px** (`--layout-section-gap`)
- 블록 사이 **32px** (`--layout-block-gap`)
- 카드/패널 안쪽 **24px**
- 제목과 본문 사이 **16px**
- 라벨과 값 사이 **4~8px**

**컨트롤 높이는 여백 사다리와 별개다.** 버튼·입력은 **36 / 44 / 48px** 세 가지만 쓴다. 기본은 44px 이며, 이는 터치 대상 최소 크기다.

## 6. Radius 토큰

| 유틸리티       | 값       | 용도                           |
| -------------- | -------- | ------------------------------ |
| `rounded-xs`   | 4px      | 인라인 표식, 포커스 링         |
| `rounded-sm`   | 8px      | 작은 요소 — 배지, 태그, 칩     |
| `rounded-md`   | **12px** | 일반 UI — 버튼, 입력, 패널     |
| `rounded-lg`   | 16px     | 큰 영역                        |
| `rounded-xl`   | 20px     | 큰 영역 상한 — 모달, 판 프레임 |
| `rounded-full` | ∞        | 아바타와 점 표시에만           |

**20px 을 넘는 값은 스케일에 없다.** `rounded-2xl`, `rounded-3xl` 은 존재하지 않는다.

**모든 요소를 둥글게 만들지 않는다.** 표, 목록 행, 구분선, 본문 블록은 각지게 둔다. 전부 둥글면 정보가 많은 화면에서 경계가 흐려지고 화면이 물러 보인다.

## 7. Shadow 토큰

그림자는 최소화한다. **위계는 그림자가 아니라 아래 순서로 만든다.**

1. **여백** — 먼저 떨어뜨려 놓는다
2. **배경 대비** — `bg-page` / `bg-raised` / `bg-sunken`
3. **경계선** — `border-subtle` → `border-line`
4. 그래도 안 되면 그림자

정말 떠 있어야 하는 것(드롭다운, 모달, 바둑돌)에만 쓴다. 목록 항목, 섹션, 본문 블록에는 쓰지 않는다.

| 유틸리티       | 용도                    |
| -------------- | ----------------------- |
| `shadow-xs`    | 거의 안 보이는 단차     |
| `shadow-sm`    | 기본 — 실제로 띄운 패널 |
| `shadow-md`    | 드롭다운, 팝오버        |
| `shadow-lg`    | 모달, 드로어            |
| `shadow-stone` | 바둑돌                  |

그림자 색은 검정이 아니라 따뜻한 갈색(`--elevation-tint`)이다. 종이 위에 놓인 것처럼 보이게 하려면 검정 그림자는 너무 차갑다.

## 8. Layout 토큰

데스크톱 중심이며 **상단 네비게이션**을 쓴다.

| 토큰                     | 값          | 용도                                      |
| ------------------------ | ----------- | ----------------------------------------- |
| `--layout-max`           | 1200px      | 기본 콘텐츠 폭 (`container-page`)         |
| `--layout-max-wide`      | 1280px      | 바둑판 + 분석 패널 (`container-analysis`) |
| `--layout-max-prose`     | 720px       | 읽기 위주의 글 (`max-w-prose`)            |
| `--layout-gutter`        | 24px        | 데스크톱 좌우 여백                        |
| `--layout-gutter-narrow` | 16px        | 좁은 화면 좌우 여백                       |
| `--layout-nav-height`    | 64px        | 상단 네비게이션                           |
| `--layout-board-min/max` | 320 / 720px | 바둑판 한 변                              |

**하지 않는 것.**

- 왼쪽 고정 사이드바를 서비스의 기본 구조로 만들지 않는다.
- 페이지마다 같은 3열 카드 대시보드를 반복하지 않는다.
- 화면을 가득 채우려고 폭을 100% 로 늘리지 않는다.

`container-page` 와 `container-analysis` 유틸리티가 최대 폭과 좌우 여백을 함께 처리한다. 페이지마다 `mx-auto max-w-[1200px] px-6` 를 다시 적지 않는다.

z-index 도 토큰이다(`--z-nav`, `--z-modal` …). 숫자를 컴포넌트에 흩어놓지 않는다.

## 9. Board 토큰

바둑판은 **카드 안의 작은 컴포넌트가 아니다.** 분석 화면에서는 화면의 핵심이며, 그래서 자기 토큰 계열을 갖는다.

색 토큰은 3절에 있고, 여기서는 **기하 비율**을 다룬다. 판 크기는 화면에 따라 달라지므로 픽셀이 아니라 **격자 간격(gap)에 곱하는 비율**로 둔다.

| 토큰                  | 값    | 뜻                           |
| --------------------- | ----- | ---------------------------- |
| `--board-stone-size`  | 0.94  | 돌 지름 ÷ 격자 간격          |
| `--board-star-size`   | 0.11  | 화점 지름                    |
| `--board-line-width`  | 0.035 | 격자선 두께                  |
| `--board-edge-width`  | 0.06  | 외곽 격자선 두께             |
| `--board-padding`     | 0.85  | 판 가장자리 여백 (좌표 포함) |
| `--board-label-size`  | 0.5   | 돌 위 수순 숫자              |
| `--board-coord-size`  | 0.42  | 좌표 문자                    |
| `--board-marker-size` | 0.42  | 마커(△ □ 등)                 |

Canvas 렌더러는 이 값을 `src/lib/design/tokens.ts` 의 `readRatio()` 로 읽는다. 숫자를 렌더러 안에 적지 않는다.

**다크 모드에서 판을 검게 만들지 않는다.** 나무 톤의 명도만 낮춘다. 판이 어두워지면 흑돌이 판에 묻혀 사라진다.

테마가 바뀌면 CSS 변수 값이 달라지지만 Canvas 는 스스로 다시 그리지 않는다. `onThemeChange()` 로 구독해 재렌더한다.

## 10. Chart 토큰

차트는 데이터를 설명하는 수단이다. **차트가 주인공이 되지 않는다.** 장식용 그래프를 만들지 않는다.

### 색을 고르는 규칙

색은 네 가지 일 중 하나만 한다.

| 일          | 언제                      | 토큰                          |
| ----------- | ------------------------- | ----------------------------- |
| Categorical | 정체성 (어느 계열인가)    | `--series-1` … `--series-8`   |
| Sequential  | 크기 (얼마나 큰가)        | `--seq-1` … `--seq-6`         |
| Diverging   | 극성 (0 기준 어느 쪽인가) | `--div-neg-3` … `--div-pos-3` |
| Status      | 상태                      | 3절의 예약된 상태 색          |

**시리즈 색은 1번부터 순서대로 배정하며 순환시키지 않는다.** 계열이 9개가 되면 색을 새로 만들지 말고 "기타"로 묶거나 화면을 나눈다. 색은 **계열에 붙지 순위에 붙지 않는다.** 필터로 계열 수가 줄어도 남은 계열의 색이 바뀌면 안 된다.

축이 두 개인 차트(`dual-axis`)는 만들지 않는다. 단위가 다른 두 값은 차트를 나눈다.

### 검증 결과

팔레트는 눈으로 고르지 않았다. 접근성 검증기(OKLab 기반 색각이상 시뮬레이션)를 돌려 맞췄다.

| 검사                          | 라이트   | 다크     |
| ----------------------------- | -------- | -------- |
| 명도 대역                     | 통과     | 통과     |
| 채도 하한                     | 통과     | 통과     |
| 색각이상 인접쌍 ΔE (목표 ≥ 8) | **11.9** | **9.8**  |
| 일반 시야 인접쌍 ΔE (하한 15) | **16.3** | **15.6** |
| 배경 대비 (≥ 3:1)             | 통과     | 통과     |

라이트 8슬롯: `#0b67a9` `#b75f2c` `#028a9b` `#9c721c` `#ae5a84` `#036a34` `#2d8ab8` `#9a322a`
다크 8슬롯: `#448bcb` `#ca774a` `#13a5b2` `#b58a3a` `#c4759c` `#418d59` `#2e97ca` `#bb584d`

토큰 파일에서 차트 색만 `oklch` 가 아니라 hex 인 이유가 이것이다. **검증기를 통과한 값 그대로**를 남겨 두었다.

> **계열 수 상한.** 위 수치는 _인접쌍_ 기준이다(막대·선·누적처럼 이웃한 것끼리만 닿는 형태). 산점도·버블·지도·small multiples 처럼 **아무 두 계열이나 나란히 놓일 수 있는** 형태에서는 8슬롯 전부가 서로 구별되지는 않는다. 그런 차트에서는 `--series-1`, `--series-4`, `--series-5` 세 개까지만 쓴다(`SERIES_TOKENS_ANY_PAIR`). 더 필요하면 계열을 합치거나 화면을 나눈다. 팔레트를 늘려서 해결하지 않는다.

색을 바꿀 일이 생기면 값을 손으로 고치지 말고 검증기를 다시 돌린다.

### 차트 기본기

- 계열이 2개 이상이면 범례를 항상 두고, 4개 이하면 직접 라벨도 단다. 정체성을 색에만 맡기지 않는다.
- 모든 점에 숫자를 찍지 않는다. 필요한 곳에만 직접 라벨을 단다.
- 격자와 축은 뒤로 물러나야 한다 (`--chart-grid`, `--chart-axis`).
- 값·라벨·범례의 **글자는 텍스트 색**을 쓴다. 계열 색으로 글자를 칠하지 않는다. 옆의 색 표식이 정체성을 전달한다.
- 표로도 볼 수 있게 한다.

### 어떤 차트를 쓰는가

- **수순별 승률** — 면적/선 그래프. 흑·백 두 계열이므로 시리즈 색이 아니라 `--winrate-black/white` 를 쓴다.
- **집 차이** — 0 을 기준으로 갈리므로 diverging 램프.
- **수 품질 분포** — 예약된 상태 색(`--move-*`). 시리즈 색을 쓰지 않는다.
- **단일 수치**(총 실수 수, 정확도) — 차트로 만들지 않는다. 큰 숫자 하나로 보여준다.

단순한 막대나 게이지는 SVG/CSS 로 직접 만든다. 축·툴팁·반응형이 필요할 때만 Recharts 를 쓴다.

## 11. Icon

Lucide 를 쓴다(`lucide-react`).

- 크기는 15 / 16 / 20 / 24px. 본문 옆에서는 텍스트 크기에 맞춘다.
- 굵기는 기본(1.5~2). 아이콘만 굵어지면 화면이 시끄러워진다.
- **아이콘만 보고 뜻을 추측해야 하는 자리에는 텍스트를 함께 둔다.** 툴바의 아이콘 버튼은 최소한 `aria-label` 과 툴팁을 갖는다.
- 장식용 아이콘에는 `aria-hidden` 을 붙인다.
- 의미 없는 배지를 만들지 않는다. 배지는 상태가 실제로 여러 개일 때만 쓴다.

## 12. Motion

목적은 넷뿐이다: **상태 변화 전달 · hover 피드백 · modal 열고 닫기 · loading.**

| 토큰              | 시간  | 용도          |
| ----------------- | ----- | ------------- |
| `--duration-move` | 90ms  | 수순 이동     |
| `--duration-fast` | 120ms | hover, focus  |
| `--duration-base` | 180ms | 상태 변화     |
| `--duration-slow` | 260ms | modal, drawer |

수순 이동이 90ms 인 것은 기보를 빠르게 넘겨볼 때 애니메이션이 밀리면 안 되기 때문이다.

`--easing-out` 을 기본으로 쓴다. 들어올 때는 빠르게 시작해 부드럽게 멈춘다.

`prefers-reduced-motion` 은 `globals.css` 에서 전역으로 처리했다. 장식 목적의 애니메이션은 만들지 않는다.

## 13. Card

**모든 정보를 카드에 넣지 않는다.** Card 는 **독립적인 정보 단위**일 때만 쓴다.

- 목록의 한 항목처럼 그 자체로 떼어낼 수 있는가 → Card
- 페이지 흐름의 한 문단인가 → Card 아님. 배경 위에 그냥 둔다

카드로 감싸기 전에 여백으로 먼저 나눠 본다. 대부분은 그것으로 충분하다. 컴포넌트 분리 규칙은 [`COMPONENT_RULES.md`](COMPONENT_RULES.md) 에 있다.

## 14. shadcn/ui 사용 방침

```bash
npx shadcn@latest add button dialog
```

`components.json` 이 `src/components/ui/` 에 설치되도록 맞춰져 있다(`rsc: false` — 서버 컴포넌트가 없는 SPA 다).

`--color-background`, `--color-primary` 같은 **shadcn 호환 별칭**을 `globals.css` 에 남겨 두었다. 받아온 컴포넌트가 곧바로 컴파일되게 하려는 것이다. **새로 쓰는 코드에서는 이 이름을 쓰지 않는다.** `bg-page`, `text-ink`, `bg-accent` 를 쓴다.

- 필요한 primitive 만 하나씩 추가한다. 전체를 미리 설치하지 않는다.
- 설치 직후 기본 색상 클래스를 우리 토큰으로 바꾼다.
- 바둑판, 승률 그래프, 수순 목록처럼 서비스 고유 UI 는 shadcn 으로 만들지 않는다. 직접 만든다.

## 15. 리뷰 체크리스트

새 화면을 올리기 전에 확인한다.

- [ ] 색·크기·간격을 코드에 직접 적지 않았다. 토큰만 썼다.
- [ ] 본문이 16px 이상이고, 가장 작은 글자도 13px 이상이다.
- [ ] 여백이 4px 배수 사다리 안에 있다.
- [ ] Card 로 감싼 것이 독립적인 정보 단위다.
- [ ] 표·목록·구분선을 둥글리지 않았다.
- [ ] 위계를 여백·배경 대비·경계선으로 먼저 만들었고, 그림자는 정말 떠 있어야 하는 것에만 썼다.
- [ ] 상태를 색만으로 알리지 않는다. 아이콘이나 문구가 함께 있다.
- [ ] 아이콘만 있는 버튼에 `aria-label` 이 있다.
- [ ] 바뀌는 숫자에 `tabular` 가 붙어 있다.
- [ ] 다크 모드에서 확인했다. 특히 바둑판이 검어지지 않았다.
- [ ] 차트가 있다면 범례가 있고, 시리즈 색을 1번부터 순서대로 썼다.
